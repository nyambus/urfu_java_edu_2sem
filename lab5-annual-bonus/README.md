# Лабораторная работа №5 — годовая и квартальная премии

Самостоятельный Maven-проект на Java 17 и Spring Boot 2.7.16. `POST /api/request` на порту **8082** проверяет вход, модифицирует `source` как Сервис 1 лабораторной №4, пересылает запрос в неизменённый `lab4-two-services/service2` на **8084**, сохраняет его успешный ответ и добавляет рассчитанные премии. Исходный `lab4-two-services/service1` одновременно на 8082 запускать нельзя: это альтернативная реализация первого сервиса. Если 8082 занят, используйте `--server.port=18082` и обращайтесь к новому порту.

## Запуск (из корня репозитория, два терминала)

```bash
# Терминал 1: неизменённый Сервис 2 лабораторной №4
cd lab4-two-services/service2
mvn spring-boot:run
```

```bash
# Терминал 2: новый Сервис 1 лабораторной №5
cd lab5-annual-bonus
mvn spring-boot:run
```

В `lab5-annual-bonus` можно вместо запуска из Maven собрать самостоятельный исполняемый JAR: `mvn package`, затем `java -jar target/lab5-annual-bonus-1.0.0.jar`. Адрес следующего сервиса задаёт `service2.url` (по умолчанию `http://localhost:8084/api/request`). Порт задаёт `server.port` (по умолчанию 8082); оба свойства можно переопределить аргументами `--server.port=...` / `--service2.url=...`.

## Проверка и кадры для отчёта

Документы и скрипт генерации отчётов хранятся отдельно от Git-репозитория. Указанные далее пути `reports/user_evidence/...` относятся к каталогу, в котором находится `reports/build_reports.py`, а не к папке `lab5-annual-bonus`. Файлы `reports/` исключены из Git и остаются на компьютере автора.

В каталоге `lab5-annual-bonus` под JDK 17 выполните `mvn -q clean package`: сборка запускает JUnit 5; отдельный запуск — `mvn test`. Проверено в этой среде: 4 теста, 0 ошибок и пропусков. Затем откройте Postman, отправьте запрос из следующего раздела и сохраните кадр с методом, адресом, кодом 200 и обоими полями премии как `reports/user_evidence/lab5-01.png`. Сохраните кадр окна тестов с фактическим результатом как `reports/user_evidence/lab5-02.png`; для отрицательного сценария `workDays=0` с кодом 400 — `reports/user_evidence/lab5-03.png`. Если сервис ЛР4/1 ещё занимает 8082, сначала остановите его либо запустите сервис ЛР5 с `--server.port=18082` и исправьте порт в Postman. После сохранения кадров из корня каталога с `reports/build_reports.py` запустите только генерацию персонального отчёта ЛР5: `py -3 -c "import sys;sys.path.insert(0,'reports');from build_reports import LABS,build;print(build(5,LABS[5],screenshots=True))"`. Запуск всего `py -3 reports/build_reports.py` перезапишет отчёты остальных ЛР, в том числе вручную доработанные.

## Запрос и ожидаемый ответ

Команды ниже рассчитаны на Bash (в том числе Git Bash на Windows), из любого каталога после запуска обоих сервисов.

```bash
curl -i -X POST http://localhost:8082/api/request \
  -H 'Content-Type: application/json' \
  -d '{"uid":"10","operationUid":"op-10","systemName":"ERP","systemTime":"2024-02-29T12:00:00Z","source":" web ","communicationId":100,"templateId":8,"productCode":1500,"smsCode":10,"position":"TL","salary":1000,"bonus":0.1,"workDays":10}'
```

Ожидается HTTP **200** и JSON с полями `uid:"10"`, `operationUid:"op-10"`, `code:"success"`, `errorCode:""`, `errorMessage:""`, `annualBonus:9516.00`, `quarterlyBonus:2366.00`; `systemTime` — текущее время ответа Сервиса 2 (UTC). Отправленный ему `source` будет `service1:web`. Сервис 2 не изменялся: новые поля входа он игнорирует, а бонусы вычисляются только после его успешного ответа.

Для DEV/HR ответ также имеет HTTP 200 и `annualBonus`, но `quarterlyBonus` равен `null` (это явный признак неприменимости, не нулевая премия). Например, с `position:"DEV"`, `salary:1000`, `bonus:0.1`, `workDays:365` и указанной датой 2024 года годовая премия равна `220.60`.

```bash
# Ошибка входа: отрицательный оклад
curl -i -X POST http://localhost:8082/api/request -H 'Content-Type: application/json' \
  -d '{"uid":"10","operationUid":"op-10","systemTime":"2024-02-29T12:00:00Z","communicationId":100,"position":"TL","salary":-1,"bonus":0.1,"workDays":10}'
```

Ответ на ошибку — HTTP **400**, `code:"failed"`, `errorCode:"ValidationException"`, оба поля премии `null`. Неподдерживаемый `uid:"123"` даёт HTTP 400 и `UnsupportedCodeException`. Некорректные JSON/перечисления, отсутствие обязательных полей, неверная календарная дата и недопустимые выплаты также дают HTTP 400. Недоступный Сервис 2, отвергнутый им запрос или пустой ответ дают HTTP **502**, `code:"failed"`, `errorCode:"DownstreamUnavailable"`, без рассчитанных премий.

## Правила расчёта

`position` обязателен и принимает `DEV`, `HR`, `TL`, `PO`, `TPM`, `CTO`. Коэффициенты из задания: DEV **2.2**, HR **1.2**, TL **2.6**. Для дополнительных должностей задание не задаёт коэффициенты, поэтому принято: PO **2.4**, TPM **2.8**, CTO **3.0**. Управленческие должности: TL, PO, TPM, CTO; DEV и HR не имеют квартальной премии. Метод `calculateQuarterly` при вызове для неуправленческой должности выбрасывает `IllegalArgumentException`; HTTP-обработчик не вызывает его для DEV/HR, возвращая `quarterlyBonus:null`.

`annualBonus = salary × bonus × число календарных дней года × коэффициент / workDays`; `quarterlyBonus` вычисляется по той же формуле с **числом календарных дней квартала даты `systemTime`** вместо дней года. Так, первый квартал 2023 г. — 90 дней, 2024 г. — 91 день. Используется григорианский календарь, включая правило вековых лет. Результат округляется до 2 десятичных знаков по `HALF_UP`. `bonus` — множитель (например, `0.1` означает 10%), а не сумма денег. `systemTime` — календарно корректная ISO-8601 дата-время, например `2024-02-29T12:00:00Z`; год и квартал берутся из указанной в строке местной даты, не из времени сервера. `salary` и `bonus` должны быть неотрицательными, `workDays` — целым положительным числом; ноль зарплаты или множителя допустим. Остальные требования к полям и ошибки Сервиса 1 наследуются из лабораторной №4.
