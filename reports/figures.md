# План реальных скриншотов

Заполнители в DOCX не являются доказательством запуска. Перед сдачей выполните указанные действия, вставьте собственные кадры вместо заполнителей и исправьте ожидаемые ответы на фактические. PowerShell: замените `curl` на `curl.exe`; POST JSON передавайте с заголовком `Content-Type: application/json`.

## ЛР №1

1. **Рисунок 1 — Сборка WAR и развёртывание в Tomcat.** Выполнить: `mvn -q clean package; запустить Tomcat с развёрнутым spring-mvc-lab.war`. Ожидается: WAR создан, в журнале Tomcat видно успешное развёртывание.
2. **Рисунок 2 — Ответы /hello и /about.** Выполнить: `curl -i http://localhost:8080/spring-mvc-lab/hello; curl -i http://localhost:8080/spring-mvc-lab/about`. Ожидается: 200, Hello, World!; 200, Козионов Илья Алексеевич, РИЗ-150110у.
3. **Рисунок 3 — Вариант /uppercase и ошибки параметра и пути.** Выполнить: `curl -i 'http://localhost:8080/spring-mvc-lab/uppercase?text=hello'; curl -i http://localhost:8080/spring-mvc-lab/uppercase; curl -i http://localhost:8080/spring-mvc-lab/unknown`. Ожидается: 200 HELLO; 400; 404.

## ЛР №2

1. **Рисунок 1 — Успешный POST-запрос сервиса.** Выполнить: `curl -i -H 'Content-Type: application/json' -d '{"uid":"1","operationUid":"op1","systemTime":"2026-10-13T12:00:00Z","communicationId":1}' http://localhost:8082/api/request`. Ожидается: 200; code=success.
2. **Рисунок 2 — Отдельные и совместные ошибки валидации.** Выполнить: `Отправить запросы для пустого uid, operationUid, systemTime; communicationId=0 и 100001; затем совместить ошибки`. Ожидается: 400; errorCode=ValidationException; перечисление нарушений.
3. **Рисунок 3 — Исключение UnsupportedCodeException.** Выполнить: `Отправить корректный JSON с uid=123`. Ожидается: ответ с errorCode=UnsupportedCodeException и пояснением.
4. **Рисунок 4 — Коллекция проверок в Postman.** Выполнить: `Сохранить предыдущие запросы в коллекции ЛР №2 и открыть её`. Ожидается: на кадре видны все кейсы.

## ЛР №3

1. **Рисунок 1 — Успешный ответ с перечислениями.** Выполнить: `POST http://localhost:8082/api/request с systemName=ERP и остальными обязательными полями`. Ожидается: код 200 и JSON-ответ с перечислениями.
2. **Рисунок 2 — INFO и ERROR в журнале.** Выполнить: `Отправить корректный запрос, затем пустой uid и uid=123`. Ожидается: в журнале видны этапы INFO и ошибки ERROR.
3. **Рисунок 3 — Проверка недопустимой системы.** Выполнить: `POST /api/request c systemName=INVALID`. Ожидается: 400 для недопустимого значения перечисления.

## ЛР №4

1. **Рисунок 1 — Одновременный запуск сервисов.** Выполнить: `запустить оба JAR; просмотреть консоли портов 8082 и 8084`. Ожидается: оба приложения слушают свои порты.
2. **Рисунок 2 — Ответ и журнал сервиса 1.** Выполнить: `POST http://localhost:8082/api/request с source=postman`. Ожидается: JSON-ответ и запись модифицированного request.
3. **Рисунок 3 — Модифицированный request и длительность в сервисе 2.** Выполнить: `после предыдущего POST открыть журнал сервиса 2`. Ожидается: изменённый source и измеренная разница времени.

## ЛР №6

1. **Рисунок 1 — Таблицы STUDENTS и учебных дисциплин в DBeaver.** Выполнить: `остановить сервер, открыть testdb/students в DBeaver, выполнить schema.sql`. Ожидается: видны две таблицы; реальное содержимое зависит от внесённых записей.
2. **Рисунок 2 — Создание и чтение студента.** Выполнить: `POST /api/students c JSON из таблицы; GET /api/students`. Ожидается: результат создания и студент в списке.
3. **Рисунок 3 — Обновление, удаление, проверка отсутствующего id.** Выполнить: `PUT /api/students; DELETE /api/students/{id}; GET /api/students/{id}`. Ожидается: изменение, подтверждение удаления, ответ об отсутствии записи.
4. **Рисунок 4 — CRUD учебной дисциплины.** Выполнить: `POST /api/subjects; GET /api/subjects; PUT /api/subjects; DELETE /api/subjects/{id}`. Ожидается: подтверждения операций и обновлённые данные.

## ЛР №7

1. **Рисунок 1 — Форма и сохранение студента.** Выполнить: `открыть /add-student-form, заполнить поля и сохранить`. Ожидается: переход в список со студентом.
2. **Рисунок 2 — Обновление и удаление студента.** Выполнить: `из /list изменить студента и удалить его`. Ожидается: обновлённая строка и отсутствие строки после удаления.
3. **Рисунок 3 — Форма и список учебных групп.** Выполнить: `открыть форму группы, добавить и затем изменить группу`. Ожидается: запись присутствует и меняется в списке.
4. **Рисунок 4 — Список эндпоинтов Actuator.** Выполнить: `GET http://localhost:8080/actuator`. Ожидается: JSON со ссылками.
5. **Рисунок 5 — Проверка состояния Actuator.** Выполнить: `GET http://localhost:8080/actuator/health`. Ожидается: status=UP при исправной БД.
6. **Рисунок 6 — Метаданные Actuator.** Выполнить: `GET http://localhost:8080/actuator/info`. Ожидается: JSON метаданных или {}.
7. **Рисунок 7 — Список beans Actuator.** Выполнить: `GET http://localhost:8080/actuator/beans`. Ожидается: JSON с beans.
